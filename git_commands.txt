Step 1 - Local repository setup

mkdir git-workflow-assignment
  makes the project folder. I then added index.html and about.html inside it.

git init -b main
  turns the folder into a git repository. -b main names the first branch main.

git status
  shows which files are untracked, modified or staged.


Step 2 - Commits, branch and merge

git add index.html about.html
  stages the two html files for the next commit.

git commit -m "Initial commit: add index.html and about.html"
  saves the staged files as the first commit.

git status --short
  short version of git status. M means modified.

git diff --stat
  shows which files changed and how many lines were added or removed.

git add about.html
git commit -m "Update about.html with project details"
  second commit, after I edited about.html.

git branch feature
  creates a new branch called feature from the current commit.

git branch
  lists the local branches. The * shows the branch I am on.

git checkout feature
  switches to the feature branch.

git add index.html
git commit -m "Add navigation bar and footer to index.html (feature branch)"
  commit on the feature branch only. main does not get this change yet.

git checkout main
  switches back to main.

git merge --no-ff feature -m "Merge branch 'feature' into main"
  merges feature into main. --no-ff makes git create a merge commit, so the
  branch shows up in the history graph instead of a straight line.

git log --oneline --graph --all --decorate
  shows the commit history of all branches as a graph, one line per commit.

git log
  full history with author, date and message for each commit.


Step 3 - .gitignore

.gitignore has two rules:
  *.log   ignores every file ending in .log
  temp/   ignores the whole temp folder

cat .gitignore
  prints the file.

git status --ignored
  also lists ignored files. app.log and temp/ show up here and not as untracked.

git check-ignore -v app.log temp/cache.txt
  tells which line of .gitignore is ignoring each file.

git add .gitignore
git commit -m "Add .gitignore to ignore .log files and temp/ folder"
  commits the .gitignore file.


Step 4 - Undo the last commit

git add contact.html
git commit -m "Add contact.html page"
  the extra commit that I then undid.

git revert --no-edit HEAD
  undoes the last commit by making a new commit with the opposite change, so
  contact.html gets deleted again. The old commit stays in the history, which
  is why I used revert and not reset (the repo was going on GitHub).

git reset --hard HEAD~1
  (not used) would also remove the last commit, but it deletes it from the
  history, so it is not safe for commits that are already pushed.

ls
  to check that contact.html is gone after the revert.


Step 5 - GitHub

gh repo create git-workflow-assignment --public
  creates an empty public repo on GitHub from the terminal. I did this only
  after all the local commits.

git remote add origin https://github.com/princekumar0509/git-workflow-assignment.git
  connects the local repo to GitHub with the name origin.

git remote set-url origin https://github.com/princeizhere/git-workflow-assignment.git
  my GitHub username changed from princekumar0509 to princeizhere, so I had
  to fix the remote url before the push worked.

git remote -v
  shows the remote url.

git push -u origin main
  uploads main with all its history. -u links local main to origin/main.

git push -u origin feature
  uploads the feature branch too.

git push
  pushes new commits after the upstream is set.

git branch -a
  lists local and remote branches.

git reflog
  list of everything that moved HEAD (commits, checkouts, merge, revert).


Step 6

git add git_commands.txt
git commit -m "Add git_commands.txt documenting all Git commands used"
  adds this file to the repo.

git commit -am "message"
  stages all changed tracked files and commits in one go. I used it when
  I updated this file.
